- [Orval mutation wrapper pattern](orval-mutation-wrapper.md) — Orval-generated mutations require `{ data: ... }` wrapper, never raw objects
- [CTEM auth flow](ctem-auth-flow.md) — JWT tokens via sessionStorage + setAuthTokenGetter; logout mutation takes void params
- [Express route ordering](express-route-ordering.md) — static sub-paths (e.g. /scans/pipeline-run) must be registered BEFORE param routes (/scans/:scanId) to avoid shadowing.
- [API server Zod imports](api-zod-imports.md) — API server cannot import zod directly; esbuild can't resolve it. Always use @workspace/api-zod generated schemas.
- [OpenAPI schema name collision](openapi-schema-collision.md) — Two root causes: (1) schema names matching auto-generated param type names cause ambiguous re-exports; fix by removing query params/bodies from spec. (2) paths added after the last schema inside components: block land INSIDE components — always insert new paths BEFORE the components: key.
- [TanStack Query queryKey required](tanstack-querykey.md) — Hooks like useGetToolRun require queryKey in query options or TS errors block Vite HMR module reloads.
- [API server logAudit userId cast](api-server-ts-quirks.md) — logAudit userId arg always needs `as any`; pre-existing TS error in esbuild build that doesn't block runtime.
- [Real scan implementation](real-scan-impl.md) — pipelineScans.ts uses nmap(-sT), Node dns/promises, fetch, tls.connect, whois, ip-api.com; async background via setImmediate; field is assetToolConfig (no s).
- [apiFetch FormData handling](apiFetch-formdata.md) — apiFetch must detect FormData body and skip Content-Type header so browser sets multipart boundary automatically.
- [Wouter Link nesting](wouter-link-nesting.md) — Never nest `<Link>` inside `<Link>` (renders nested `<a>` which breaks JSX). Use onClick+navigate on the outer div instead.
- [Port Scanner Engine](port-scanner-engine.md) — Naabu+Masscan+Nmap+Shodan engine; masscan requires CAP_NET_RAW (graceful fallback when denied); naabu zip auto-extracts to /tmp/naabu; masscan tries system→apt→fail.
- [Recursive dir fuzzing](recursive-dir-fuzz.md) — dirFuzzer.ts uses BFS queue: depth 0 uses WORDLIST/WORDLIST_MINI, depth 1-3 uses WORDLIST_RECURSIVE; max depth=3, max 2000 endpoints/host; depth+parentPath on FuzzedEndpoint.
- [Scan Queue Architecture](scan-queue-architecture.md) — In-process FIFO queue; MAX_CONCURRENT_SCANS=5, MAX_PARALLEL_ASSETS=3; enqueueAndRun() is the single entry point; status goes pending→running→completed/failed.
- [Email circular import avoidance](email-circular-import.md) — email.ts imports platformSettings.ts; notifier.ts imports email.ts. Break the loop: define AlertEmailEvent inline in email.ts rather than importing NotificationEvent from notifier.ts.
- [Findings table cvss column](findings-schema.md) — DB column is `cvss` (real/float), not `cvssScore` (string). findingInserts must use `cvss: 7.5` not `cvssScore: "7.5"`.
- [Postgres RLS setup](postgres-rls.md) — RLS enabled on 22 tenant-scoped tables using current_setting('app.tenant_id'); policy name is tenant_isolation; run via executeSql in code_execution (tsx not available in scripts for node-postgres).
- [Stripe integration pattern](stripe-integration.md) — stripeClient.ts + webhookHandlers.ts in lib/; webhook registered BEFORE express.json() in app.ts; initStripe() in index.ts wraps in try/catch so missing integration just warns; Stripe schema init runs via runMigrations() on every startup.
- [Sessions table + recording](sessions-feature.md) — sessionsTable in lib/db/schema/sessions.ts; session recorded on login in auth.ts (tokenHash=sha256 of accessToken); UA parsed inline (no library); GET/DELETE /auth/sessions routes in routes/sessions.ts.
- [Drizzle undefined column crash](drizzle-undefined-column.md) — Passing undefined column refs to db.select({}) causes Object.entries(null) crash in orderSelectedFields; assetsTable has no `status` or `riskScore` — use verificationStatus and riskLevel instead.
- [Favihunter Python subprocess](favihunter-integration.md) — Never set PYTHONPATH in subprocess env; the wrapper script adds sys.path internally. Setting PYTHONPATH externally breaks urllib3 resolution and silently fails.
- [NVD rate limit upgrade](nvd-rate-limit.md) — Without API key: 5 req/30s → use 6500ms delay. With key: 50 req/30s → use 650ms delay. Pass key as `apiKey` header (not Authorization). Stored in platform settings as nvd_api_key.
- [EPSS/KEV enrichment](epss-kev-enrichment.md) — lib/epssKev.ts: batch EPSS via first.org API (100/batch), KEV set cached 24h from CISA; enrichFindingsWithEpssKev() wraps both; called in pipeline after dedup, before insert; non-CVE IDs (EXP-PORT-*, CLOUD-*, VT-*) are passed through unchanged.
- [Exposed port findings in pipeline](exposed-port-findings.md) — pipelineScans.ts adds EXP-PORT-{port}-{slug} findings for 26 dangerous ports after portScanReport is available (findingInserts push at end of VirusTotal block); port data from portScanReport.ports[].port.
- [FindingDrawer tab state](finding-drawer-tabs.md) — FindingDrawer now has internal activeTab state (Details/Headers/Screenshots/Comments); initialMode prop sets initial tab; Comments tab uses useListFindingComments + useCreateFindingComment; CommentsPanel is a standalone component inside FindingsPage.tsx.
- [LLM abstraction layer](llm-abstraction.md) — lib/llm.ts exports llmComplete(messages, options) + isLLMAvailable(); uses OPENAI_API_KEY env var; returns null on missing key so routes can fall back to templates. Model: gpt-4o-mini. Direct fetch to OpenAI API, no SDK dependency.
- [Audit log immutability](audit-immutability.md) — PostgreSQL trigger `enforce_audit_log_immutability` on audit_logs BEFORE UPDATE OR DELETE raises exception; function is SECURITY DEFINER. Created via executeSql in code_execution; survives DB restarts.
- [Attack surface graph API](attack-surface-graph.md) — GET /graph/attack-surface returns Neo4j-style {nodes, relationships, meta}. Node ID prefixes: org-, asset-, port-, finding-, cve-. Relationships: OWNS, SUBDOMAIN_OF, RESOLVES_TO, EXPOSES, HAS_VULNERABILITY, REFERENCES_CVE. Frontend uses D3 force simulation with zoom/pan/drag.
- [Security middleware order](security-middleware-order.md) — In app.ts: helmet() → Stripe raw webhook → CORS → express.json → auth rate limiter (/api/auth/*) → global limiter (/api) → router. Helmet has contentSecurityPolicy:false + crossOriginEmbedderPolicy:false for proxy compat.
- [Pipeline scan finalization](pipeline-scan-finalization.md) — finalizeScannedAssets() in scanScheduler.ts must be called after executePipeline() in pipelineScans.ts enqueueAndRun(); it updates lastScannedAt, risk scores, and factors in businessImpact. Without this call, risk data stays stale after real scans.
- [Compliance evidence field name](compliance-evidence-field.md) — API returns evidence (string, JSON-encoded array), not evidenceFiles. Frontend must parse JSON.parse(c.evidence) to get file list; the EvidenceFiles component accepts the raw string and parses internally.
- [Beat scheduler supersedes scanScheduler](beat-scheduler-primary.md) — beatScheduler.ts handles both asset-frequency and schedule-based scans via enqueueOrRun(). The legacy scanScheduler.ts runScheduler() used setTimeout simulation and is redundant; do not start it alongside beatScheduler. Only finalizeScannedAssets export from scanScheduler.ts is still used.
- [toAssetResponse explicit field list](asset-response-fields.md) — assets.ts toAssetResponse() manually lists every field; new DB columns (e.g. businessImpact) must be explicitly added or they silently vanish from all API responses.
- [pipelineScans variable name mismatch](pipeline-variable-names.md) — getPlatformSetting("shodan_api_key") is stored as `shodanKey`; PassiveDiscoveryOptions expects `shodanApiKey`. Pass as `{ shodanApiKey: shodanKey }` — mismatch causes silent ReferenceError in setImmediate background task.
- [Beat scheduler poll interval](beat-scheduler-interval.md) — beatScheduler.ts must poll at 60s intervals (60 * 1_000), NOT hourly. Hourly polling breaks schedule-based scans set to "hourly" frequency.
- [AlertsPage trigger type values](alerts-trigger-types.md) — Frontend must use backend-defined values: "any", "new_finding", "critical_finding", "high_finding", "scan_complete", "brand_threat". Frontend had wrong values ("new_vulnerability" etc.) that silently fell through to default in shouldRuleFire().
- [Two auth files coexist](auth-dual-files.md) — auth.ts (real: in-memory _token + sessionStorage ctem_token) and auth.tsx (React Context, unused by pages) both exist. TS resolves .ts first, so auth.tsx is effectively dormant. All pages use useAuth from @/hooks/useAuth (Zustand) or getToken from @/lib/auth (resolves to auth.ts).
