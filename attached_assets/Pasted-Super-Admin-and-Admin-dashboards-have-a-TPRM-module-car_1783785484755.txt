Super Admin and Admin dashboards have a TPRM module card (like AI Mapper's admin page) that shows every tenant and lets them flip the module on/off per client
By default the module is disabled for all client tenants; admins must explicitly enable it
Once enabled, clients land on a TPRM Dashboard (/tprm) showing: overall security rating, vendor risk breakdown, digital exposure coverage, infrastructure attack vector coverage, and a summary table of all vendors
The Vendors list page (/tprm/vendors) shows all 3rd-party companies: name, risk score, type, domain, inherent risk, scan frequency, external assets, status, industry — with an "Add Vendor" flow
Super admins can create "global" vendor entries (shared library visible to all tenants); admins can create tenant-scoped vendors; clients can also create their own vendors if the company doesn't appear in the global list
The "Add Vendor" dialog searches a global shared library first; on entering a domain it calls a real enrichment endpoint that checks Brandfetch, autocomplete.clearbit.com (no-auth free tiers), and DNS to return company name, industry, size, logo, and confirms whether this domain is already in the global library under a different name
If the domain IS already in the global library it shows: "This domain is associated with [Company Name] — use that company or continue creating a new one"
Each vendor gets live scanned on creation and on schedule: DNS records, HTTP probing, SSL/TLS grading, open ports via Shodan InternetDB, subdomains via crt.sh, tech detection, security header grading, .env/.git exposure, VirusTotal domain score (if key configured) — all using real network calls, zero mocked data
Vendor detail page (/tprm/vendors/:id) shows: company snapshot (logo, industry, location, size, founded, market cap pulled from enrichment API), cyber posture rating, risk rating breakdown by category (Network / DNS / Web App / Email / Cloud / Endpoint / TLS / Information Leak / Digital Reputation), posture trend chart, assets list, findings list, remediation tasks, dark web mentions count, rating history chart, 4th-party vendor section
4th-party vendors are auto-discovered during the vendor scan by analysing HTTP response headers (CDN/WAF providers), DNS CNAMEs, JS file third-party calls, and SSL cert issuer chains — each discovered 4th-party is shown with its own risk contribution score
Supply Chain page (/tprm/supply-chain) shows a risk-by-business-impact matrix, suppliers with critical findings, and a filterable table of all supply chain nodes (software components, SaaS dependencies, API integrations)
TPRM Admin console (/tprm/admin) lets super admins see all tenants' module status and toggle enable/disable; also manage the global shared vendor library
All findings from vendor scans surface as real CVSS-scored entries, are enriched via the existing EPSS/KEV pipeline, and are visible in the vendor detail findings tab
Risk score (0–100) maps to letter grades A+/A/B/C/D/F; breakdown by 9 security categories matches the docx spec
Assessment types: Continuous (re-scanned on scan_frequency schedule) and One-Time; shown on vendor summary with status badges
Module is guarded by requireTprm middleware on all API routes and a RequireTprm React component on all frontend routes (same pattern as AI Mapper)
Sidebar shows "Third Party Risk" nav section (only visible when module enabled) with sub-links: Dashboard, Vendors, Supply Chain, Compliance, Questionnaires
Admins can build security questionnaire templates (drag-and-drop question builder: text, yes/no, multi-choice, file upload, 1–5 rating) and send them to any vendor with a due date and recipient email; vendors fill out their answers through a public portal link (/tprm/respond/:token) — no login required; responses are auto-scored and factored into the vendor's overall risk score
Compliance document management tracks SOC2 Type I/II, ISO 27001/27017/27018, PCI DSS, HIPAA, GDPR, and NIST attestations per vendor; each document has an audit period, auditor, expiry date, and downloadable file; a beat scheduler job fires expiry reminder alerts 30 days before expiry via email/Slack/webhook
A tenant-wide compliance board shows all vendors × required document types as a green/amber/red grid so compliance gaps are immediately visible
Admins can upload a CycloneDX JSON/XML or SPDX JSON/tag-value SBOM file for any vendor; the platform parses all components, cross-references them against the OSV API (free, no key required) and existing NVD/KEV pipeline, and surfaces vulnerable components in the Supply Chain tab with CVSS scores, EPSS, and KEV flags — zero mocked data
